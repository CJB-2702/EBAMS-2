# Phase 1 — Relationship Control Layer

Give assets a **dedicated, intention-revealing relationship API**, make every attach/detach
**auditable as an Event**, and make reparenting **correct across the whole subtree** — all on
the existing schema, with no migrations.

## Goal

A caller holding an `AssetContext` for asset *N* can `attach_child(child_id)`,
`detach_child(child_id)`, and `attach_children([...])`. Each call: guards cycles, reparents
the child onto *N* (or to null on detach), cascades `root_asset`/`depth_from_root` to the
child's whole subtree, writes the structured `AssetParentHistory` row, and emits one `Event`
linked to **both** assets. A new `AssetTreeStruct` materializes the nested tree to a requested
depth for the Phase 2 UI to render.

## In scope

- NEW `AssetRelationshipManager` — `attach_child`, `detach_child` (one at a time, no batch —
  DR4), owning the move logic (cycle guard, root/depth recompute, history row, eventing).
  ([D1](../decisions.md))
- NEW `AssetTreeStruct` — nested, depth-bounded tree read model with `to_dict()` and a
  `level(depth)` slice for HTMX expansion. ([D2](../decisions.md))
- **Subtree cascade** — reparent recomputes root + depth for **all descendants**, one
  transaction (fixes the existing single-node bug). ([D5](../decisions.md))
- **Eventing** — one `Event` per change, dual-linked via `AssetEvent` (`role` `parent`/
  `child`), reusing the `_emit_event` pattern; new `AssetEventNarrator.child_attached` /
  `child_detached`. `AssetParentHistory` still written. ([D3](../decisions.md))
- NEW `RelationshipPolicy` (seam) — "may C be a child of N?" **structural-only** check:
  rejects self-parent and cycles; cross-domain and cross-class attach are allowed (OQ2
  resolved). ([D8](../decisions.md))
- `AssetContext` exposes the new manager (`.relationships`) and tree struct.

## Out of scope

- All UI, routes, templates, the Configurations entry — Phase 2.
- Any schema change / migration — none needed ([`../existing_seams_audit.md`](../existing_seams_audit.md)).
- Reworking `AssetHierarchyStruct` (ancestors/breadcrumbs) — left as-is.

## Dependencies

- Existing `Asset` hierarchy columns, `AssetParentHistory`, `AssetEvent` (+`role`), `Event`,
  `AssetEventNarrator`, and the `AssetHierarchyManager.reparent` logic being absorbed.

## Deliverables

- `app/assets/control_layer/managers/asset_relationship_manager.py` — `AssetRelationshipManager`.
- `app/assets/control_layer/domain_structs/asset_tree_struct.py` — `AssetTreeStruct`.
- `app/assets/control_layer/guards/relationship_guard.py` — `RelationshipPolicy`.
- New narrator methods on `asset_event_narrator.py`.
- `AssetContext.relationships` property + tree accessor; `reparent` delegates to the new
  manager (single write path, [D8](../decisions.md)).
- Unit tests covering cycle, cascade, detach-to-root, eventing, bulk atomicity.

## Exit criteria

- [ ] `AssetContext(n).relationships.attach_child(c)` sets `c.parent_asset = n`, recomputes
      `c.root_asset`/`depth_from_root`, **and** updates every descendant of `c` in the same
      transaction.
- [ ] Detaching a child sets its parent to `null`, makes it `root_asset = itself`,
      `depth = 0`, and re-roots its whole subtree.
- [ ] Attempting to attach an asset under one of its own descendants is **rejected** with a
      clear message (cycle guard) and writes nothing.
- [ ] Every successful attach/detach creates exactly **one `Event`** with `EventType.ASSET_MANAGEMENT`,
      linked by **two** `AssetEvent` rows (`role="parent"` and `role="child"`), and the
      titles come from `AssetEventNarrator`.
- [ ] Every successful change writes one `AssetParentHistory` row capturing previous/new
      parent, root, and depth.
- [ ] `AssetTreeStruct.from_id(n, max_depth=d).to_dict()` returns a nested tree whose node
      depths and child nesting are correct, and `.level(k)` returns exactly the assets at
      depth *k* relative to *n*.
- [ ] No migration is generated by this phase (`makemigrations` reports no changes).
