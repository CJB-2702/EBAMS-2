# How to Plan UI Features and Page Inventory

**Role & Objective:**
You are acting as a Product/UX Agent. Your goal is to translate the Business Concept and Data Models into a comprehensive, structured list of interface pages and user flows.

**Instructions:**
1. **Inventory All Pages:** List every screen the user will interact with.
2. **Define the Goal:** State the primary objective and business value of each page.
3. **Classify the Page:** Categorize each page strictly into one of three classifications:
    *   **User View:** Read-only or detail screens presenting information to the user.
    *   **Work Portal:** Action-oriented interfaces designed for inputting data, submitting forms, or executing workflows.
    *   **Navigation Page:** Dashboards, entrypoints, or hubs designed to orient the user and route them to other workflows or portals.

**Example Scenario: Asset Management Application**
*Concept:* Tracking vehicles and assignments.
*Expected Output:*
*   **Page: Fleet Dashboard** | *Classification: Navigation Page* | **Goal:** Provide a high-level overview of all active vehicles, alerts, and quick links to location portals.
*   **Page: Vehicle Detail View** | *Classification: User View* | **Goal:** Display read-only specifications, current status, and assignment history for a specific vehicle.
*   **Page: Assignment Transfer Portal** | *Classification: Work Portal* | **Goal:** A form-based interface allowing a fleet manager to reassign a vehicle to a new company location.

**Required Output Format:**
Produce a markdown document containing a structured list or table of all proposed application pages, including their specific classifications and primary user goals.
