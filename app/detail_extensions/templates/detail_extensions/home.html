    Detail Extensions

    Extending Assets and Models with dynamic, policy-driven custom tables.

    tune Configure Policies
    settings_input_component Creation-Time Provisioning Workflow

    Detail Extensions are not rigid columns on core tables. Instead, they are modular tables mapped via a policy-driven enablement registry. They are provisioned dynamically when assets or models are created.

    How It Triggers:

    1. Signal Emission: When a new Asset or AssetModel is successfully saved, a creation signal (asset_created or asset_model_created) is dispatched.
    2. Orchestration Fan-In: The DetailExtensionCreationOrchestrator listens to these signals and schedules a post-commit transaction hook using transaction.on_commit().
    3. Post-Commit Provisioning: Once the parent transaction commits, the AssetExtensionProvisioner or ModelExtensionProvisioner runs in its own transaction context.
    4. Isolated Factory Creation: The provisioner queries the active configuration policies (assigned asset classes/models) and runs the corresponding extension factory to instantiate blank extension rows. Failed extensions are logged and skipped, preventing one bad extension from breaking core creation flows.

    Note: Idempotency is tracked in AssetExtensionProvisioningState. Extensions are only created once per key, supporting safe future backfills or manual enablement.

    rule Configuration Instructions

    To control which assets or models receive which detail extensions, you manage assignment policies in the Configuration Portal:

    1. Navigate to the Configuration Landing Page.
    2. Review the registered extensions in the catalog (e.g. Purchase Information, Vehicle Registration, Emissions Specifications).
    3. Click Configure on the target extension to open its Assignment Editor.
    4. Enable or disable the extension for specific Asset Classes or individual Asset Models using the in-page assignment matrices.
    5. Click Save Assignments. All newly created assets or models under those scopes will automatically trigger provisioning.
