    • {% endblock %} {% comment %} THE CREATE-SHIPMENT WIZARD — one route, vertical scroll, progressive enablement, session-backed draft. The create-PO wizard's mirror, one level down the chain: that page finds open DEMANDS and associates them with the order lines it is building; this page finds open ORDER LINES and associates them with the arriving lines it is building. Nothing on this page touches the database until "Create Shipment". Every control posts to this same URL, mutates `request.session`, and redirects back here, so a refresh at any point restores exactly what the receiver had staged. Later cards are SHOWN but disabled until earlier ones validate — server-side, from the draft, not from JavaScript, because a JS-only gate fails the moment the page reloads. WHAT CHANGED FROM THE FLAT FORM. Copy-on-create still exists and is still the default: a line nobody allocates by hand is matched to the header order's line by part at commit, exactly as before. What the flat form could not do was let the receiver say otherwise BEFORE the record existed — every correction meant creating the shipment, landing on the edit page, and undoing a guess. The ambiguous cases (two order lines for the same part, material split across two orders, a part the header order does not buy at all) are precisely the ones a guess gets wrong, and they are now answerable up front. {% endcomment %} {% block extra_css %} .wizard-step-disabled { opacity: 0.55; } {% endblock %} {% block content %}
