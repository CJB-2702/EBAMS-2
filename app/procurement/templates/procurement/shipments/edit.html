    • {% endblock %} {% comment %} THE PO SECTOR'S EDIT & LINKAGE, INVERTED. Same page, same four blocks, same master-detail: header edit, add a line, lines list on the left, linkage on the right. What differs is only the direction of the link — the PO page links each ORDER LINE to the DEMANDS it satisfies; this links each ARRIVING LINE to the ORDER LINES it answers for, potentially across several vendors' open orders. The right column is a TOP-BOTTOM search tool, the same shape the PO page uses: current links first, then a filter bar over a results list with a per-row action. It was a stack of wide cards before, which read as a browse surface when the job is a lookup. Two things the PO page has no equivalent of, and why they stay: A QUANTITY ON EVERY ROW. The PO side's row action is "Allocate all", because a demand is claimed whole. Here partial allocation is the ordinary case — one box routinely answers two order lines — so each row carries its own quantity, defaulted to whatever is still unallocated. THE AUDIT COMMENT. Past local delivery every mutation costs a mandatory reason plus a pre-state snapshot. The PO side's equivalent is automatic and silent; here it is a required field, so it is rendered inline on each form rather than discovered on submit. NO DRAG-AND-DROP. This page's job is "find the right PO line for this one arriving line", which is a search problem, not a sorting problem. The bulk sorting tool is the Basic Shipment Manager. Selection round-trips through ?line_id= so a reload or a bookmark reproduces it, and so shipment detail's per-line "Edit assignment" can deep-link straight in. {% endcomment %} {% block extra_head %} {% endblock %} {% block content %}
