{% comment %} The popup demand picker — the search-dropdown's wide sibling. A UTILITY, not the primary path. Picking a demand is normally one keystroke in the dropdown; this exists for when the operator needs to see requester, need date, and outstanding quantity side by side before deciding, or needs to cut through a large open-demand pool with the same filter set as `demand_index` (procurement/demands/index.html). Selecting a row writes back into the `` through its public API (`value` + `value-label`) rather than swapping a hidden input, so the field's visible text and its submitted value cannot drift apart. Read-only browsing with a single-value pick is exactly what a modal is for (harness/UX_UI/design_patterns/modals.md) — nothing is assigned here, the receipt is still built on the page behind it. Picking stays single-row: the filters below narrow a list you choose ONE demand from, never a batch. Every filter field lives inline in this one dialog rather than behind a second "Filters" button — a dialog opening a dialog is a nested modal, which UX_UI/design_patterns/modals.md rules out. {% endcomment %}
