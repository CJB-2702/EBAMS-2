List Management

Seven ways to select, assign, and build lists of items — modeled around adding supplier items and aliases to a new Part record.

Every list on this page — parts, supplier items, aliases — is hardcoded demo JSON rendered directly into the page. Nothing here reads from or writes to the database; compare against the real creation form at /parts/new/.

Note: any card built around a large search area can double as a create/add form as needed, via a search/create toggle in the card header — not just a pure picker. The Left-Heavy Assignment Card Pair, Top and Bottom Filterable List Table Pair, and Top and Bottom Search Select Wide Cards Pair all demonstrate this toggle live.

Left/Right Search & Select Tools

Two-pane (or single-pane) pickers where the source pool and the result sit side by side rather than stacked.

1. List Box (Single Panel)

A single searchable multi-select panel with no "available vs. assigned" split — best when the choice is flat (pick several from one list) rather than a two-sided assignment. Full component API: <list-box>.

3. Left-Heavy Assignment Card Pair

A large, searchable pool on the left (2/3 width) assigns into a lighter target list on the right (1/3 width) — used when the available pool is too large to browse as a plain multi-select, so it needs its own search box, sortable table, and select-all header checkbox. The left card's header carries the same search/create toggle as §6 and §7 — switching to create mode swaps the search bar and table for a create form, and the footer's primary button adds the new item straight to "On This Part". See harness/UX_UI/design_patterns/left_heavy_assignment_card_pair.md.

Top and Bottom Selection Tools

Pickers where the search/create step stacks above (or below) the resulting list or detail card, rather than sitting beside it.

Naming system. Every pattern below is named <Selection Type> + <Display Type> Combo (the picker and its results share one card) or Top and Bottom <Selection Type> <Display Type> Pair (the picker and its results are two separate stacked cards).

Selection types

  • Select — implies the <search-dropdown> web component.
  • Dropdown — a standard <select> dropdown.
  • Filterable list — a single input filtering a selectable table.
  • Search select — a search/filters form paired with a selectable items table.

Display types

  • Mini cards
  • Wide cards
  • Table

Not every combination is built here — e.g. a Dropdown + Table Combo (a dropdown with table rows showing your selection, in one card) would follow the same system without appearing on this page.

4. Select + Mini Cards Combo

Search an existing pool via typeahead; each pick renders as a small removable tile rather than a table row or listbox option. This is the same .fb-grid/.fb-tile markup <add-comment> uses for its staged-file previews, generalized here to any searched-and-picked item instead of just uploaded files.

5. Select + Wide Cards Combo

Search or pick an item and it's appended as a full-width, comfortably-spaced detail block underneath, inside the same card — same append-on-pick behavior as the mini-card combo (§4), just with a wide detail block instead of a small tile. Each block is square-cornered content nested inside the chamfered parent card, the same "chamfer marks a container, its contents stay square" rule as everywhere else in the app — which is also what keeps this visually distinct from the two stacked cards of §6.

Search above to preview a supplier item's full details.

6. Top and Bottom Filterable List Table Pair

A newer concept, still being validated: the top card handles adding the next item, and toggles between two modes via the icon pair in its top-right corner — search (the same searchable-table content as the left side of the left-heavy assignment card pair, §3) for assigning an existing supplier item, or create for one that doesn't exist in the pool yet. The bottom card holds a table of items already on the record, in line with the search-on-top/results-below shape of the other patterns on this page.

7. Top and Bottom Search Select Wide Cards Pair

A filters-and-results layout like Search Page Example, scoped down to the same three fields as the §6 create form (Manufacturer P/N, Manufacturer, Description) — but picking a result doesn't navigate anywhere; each row's arrow button appends a full-width detail card to the stack below, same as §5's wide card. The header's search/create toggle switches to the same create form as §6 for items that don't exist in the pool yet.
