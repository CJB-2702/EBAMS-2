Design Intent & API

Same light-DOM-submission rationale as <file-upload>: this component only owns the chrome and the pre-submit file preview grid (styled like <file-browser>'s tiles). The actual POST, HTMX swap, and server-side validation are the caller's concern.

Attributes

  • mode="edit" — switches chrome to an editing card (Cancel button, "Save" submit label, existing attachments render alongside newly-staged ones).
  • placeholder, content, error, depth — as in a normal comment card.
  • cancel-url, reload-url — edit-mode-only HTMX endpoints for Cancel / Clear.
  • existing-attachments — JSON array of {id, name, size, is_image}, rendered in the same tile grid as newly-picked files, each with a remove/restore toggle.

Comment-filter behavior

The Human / All / Machine toggle above the demo thread is window.__filterComments (static/web_components/app_specific/comment_filter.js) — a small shared function, not a custom element, scoped to the nearest .card ancestor so multiple comment cards on one page stay independent.
