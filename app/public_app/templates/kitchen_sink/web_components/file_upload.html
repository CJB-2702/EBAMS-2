upload_file

<file-upload>

Bulma-styled file field. Renders a real <input type="file"> into the light DOM so it submits natively with the enclosing form.

{# Live Demo #}
Live Demo

This demo form does not submit anywhere — it only shows the component's selection UI. No files leave your browser.

{# API & Documentation #}
API & Properties

Deliberate anti-pattern

Same rationale as <search-dropdown>: a file field's chrome and interaction are uniform and simple enough that reproducing Bulma's .file.has-name markup inside the component is easier than any alternative. The real <input type="file"> lives in the light DOM (no shadow root), so it participates natively in the enclosing <form> and submits with request.FILES.getlist(name) exactly like a hand-written field.

Attributes

  • name — form field name (default file).
  • accept — passed through to the native input.
  • multiple — allow multiple file selection.
  • label — button text (default "Choose file…").
  • size — Bulma size class, e.g. is-small (default), is-medium, is-large.
  • fullwidth — the choose CTA spans the whole card width.
  • empty-text — text shown when no file is selected.

Guardrail

Logs a console warning if the enclosing form is missing enctype="multipart/form-data" — otherwise files silently never reach the server.
