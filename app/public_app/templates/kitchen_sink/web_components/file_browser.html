<file-browser>

Progressive-enhancement browser over a light-DOM set of file links — tiles/list view, search, type and uploader filters, sort.

{# Live Demo #}
Live Demo
{# API & Documentation #}
Design Intent & API

The server renders one plain <a class="fb-item"> per file as a light-DOM child, with metadata on data-* attributes — that markup is the F5-safe fallback with JS off. With JS on, the component hides the raw links and paints a toolbar (search, type/uploader filters, sort, tiles/list toggle) over a re-rendered grid or table. All filtering/sorting happens client-side over the child nodes; no server round trips.

Expected child markup

<a class="fb-item" href="/download/..."
   data-name="spec.pdf" data-caption="Rev A" data-type="document"
   data-thumb="/inline/..." (optional, images only)
   data-size="284119" data-date="2026-05-14T09:32:00Z"
   data-user="Jane Doe" data-date-display="May 14, 2026" data-id="...">
  <span slot="actions"> ...server-rendered per-item actions... </span>
</a>

Attributes

  • default-view — tiles (default) or list.
  • storage-key — localStorage key the chosen view is persisted under.

Public methods

  • el.setView("tiles"|"list") — programmatic view switch (used by a page-level "toggle all" control).
