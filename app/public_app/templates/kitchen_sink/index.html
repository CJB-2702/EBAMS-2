Page Structure — Hero Container Pattern

Rule: Every page must have a consistent header structure:

Required elements in every page header:

  1. Top navigation bar — consistent app chrome across all portals (brand + portal tabs)
  2. Page hero container — wraps title, subtitle, and primary action buttons
    • Left side: Page title (large, bold) + subtitle (context/description)
    • Right side: Primary action buttons (Create, Export, Settings, etc.)
    • Left border accent: 4px solid primary color
    • Never combine title and actions inline — always flex layout with space-between
  3. Quick details / stat bar (optional) — below hero for key metrics
  4. Main content area — cards and forms below the hero

The hero pattern creates visual hierarchy: every user immediately knows what page they're on (title), what they can do (actions), and how healthy the data is (stats). The top nav provides consistent navigation across portals.

HTMX Patterns Demo

format= density switcher

Same canonical URL, different format= query value. Never combine density + htmx-* values.

GET /assets?format=condensed GET /assets?format=medium GET /assets?format=large

HTMX fragment format values

GET /assets?format=htmx-search-results GET /assets?format=htmx-focused

OOB success toast pattern

OOB swap pattern: POST → 303 redirect → HTMX fetches full page → hx-select extracts component → OOB swap injects #toast-container success message.

Session draft flow

Multi-step on one URL: persist draft in request.session['event_draft']. Each sub-component POSTs to update session (no DB commit). Full page at same URL always restores state — F5 rule satisfied.
