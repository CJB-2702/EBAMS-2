{% comment %} Single comment row — one comment bubble: author/timestamp, revision/edit/delete actions, body text, and attachment mini-cards. Extracted out of comments_card.html's loop so it can also be demoed standalone (kitchen sink "Isolated Components" section). Expects: row={comment, comment_hash, attachments}, event_hash. Optional: row_depth (e.g. "depth-3") — lets a caller escalate past whatever depth its own wrapping card already sits at. Defaults to "depth-2". Optional: action_depth — depth for the row's own nested surfaces (plain action buttons, attachment mini-cards): must be one step past row_depth or they'll match the row's background and disappear. Defaults to "depth-3" (the correct next step when row_depth is left at its own default of "depth-2"). Callers that escalate row_depth must escalate action_depth too. Shares id="comment-row-{hash}" with comment_edit_form.html so the Edit button's HTMX outerHTML swap can go in either direction (view <-> inline edit form). Optional: next — redirect target for the delete form's plain-POST fallback, threaded down from comments_card.html for callers outside the events app. Carries `sharp-corners` (see docs/UX_UI/components/chamfers.md): a comment row is a small repeated bubble inside an already-chamfered thread card, and stacking 20px cuts inside 20px cuts reads as noise. The composing surfaces around it — the Comments card itself and the Add/Edit Comment card () — keep the app-wide bevel, so the chamfer marks "container" and the square rows read as the content inside it. Every app's activity thread renders through this one fragment, so the class belongs here rather than on any caller. {% endcomment %}
