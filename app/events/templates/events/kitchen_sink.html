    Kitchen Sink — Thread Cards

    Reference render of the reusable comment / gallery / files card fragments, driven by one real sample event.

    Each section below is sourced independently from whichever real thread in the current database has the richest data for that fragment — a Part's comments, documents, and gallery each live on separate underlying thread rows, so no single sample carries all four at once. This proves the fragments render correctly for real, varied data rather than fixtures built to fit.

    On this page

    Feature matrix 1. Event composite card 2. Comments only 3. Gallery only 4. Files only Isolated components Comment utilities File utilities Gallery utilities

    Feature matrix

    All three surface families share one underlying table (event, via FamilyThreadManager — see events/models/event.py) and differ only in which capabilities are switched on.

    Thread type Comments Direct attachments Metadata shown to user
    Event Yes Optional (allow_direct_attachments) Yes — type, status, priority, start/end, domain, etc.
    Activity thread Yes Yes No — subordinate to the owning item (e.g. a Part); the item's own access rules govern visibility, not this row.
    FileSet No — off by construction Yes No
